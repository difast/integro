# Telegram-бот: интеграция с сайтом и панелью заявок

Клиент пишет боту в Telegram → Update приходит на Webhook сайта → клиент, сообщения и заявка сохраняются
в базе и видны в админке (раздел «Обращения», фильтр «Telegram») → оператор отвечает из админки → ответ
уходит клиенту через Telegram Bot API, админка показывает подтверждение отправки.

**Статус проверки (20.10.2026).** Код и тесты готовы. Запросы к настоящему Telegram Bot API **не
выполнялись**: в среде разработки нет токена бота, а домены `api.telegram.org` и `core.telegram.org`
недоступны. Методы и поля сверены по типам Bot API из пакета `@grammyjs/types` 5.0.0 (в нём приведены тексты
официальной документации). Интеграцию нужно проверить на сервере по разделу 4 — до этого она не считается работающей.

---

## 1. Как устроено

Telegram подключён к **общей системе обращений**, в которой уже работает MAX (`MAX_INTEGRATION.md`): общие
таблицы, сценарий, тексты, очередь отправки и админка; у каждого канала — свой адаптер.

| Часть | Где | Что делает |
| --- | --- | --- |
| Webhook | `src/app/api/telegram/webhook/route.ts` → `src/lib/chat/webhook.ts` | `POST /api/telegram/webhook`: проверяет `X-Telegram-Bot-Api-Secret-Token`, размер и JSON, сохраняет Update в `chat_events` (ключ `tg:<update_id>`) и сразу отвечает `200` |
| Разбор Update | `src/lib/telegram/types.ts` | Личные сообщения, команды, нажатия кнопок, контакт, блокировка/разблокировка бота; группы, каналы и боты игнорируются |
| Адаптер | `src/lib/telegram/adapter.ts` | Кнопки → `InlineKeyboardMarkup`; кнопка «Отправить мой номер» → `ReplyKeyboardMarkup` с `request_contact`; снятие клавиатур |
| Bot API | `src/lib/telegram/api.ts` | `getMe`, `getWebhookInfo`, `setWebhook`, `deleteWebhook`, `sendMessage`, `answerCallbackQuery`, `editMessageReplyMarkup` |
| Настройки | `src/lib/telegram/config.ts` | Переменные окружения и их проверка |
| Общее ядро | `src/lib/chat/` | Обработка событий, сценарий, очередь отправки, запросы админки |
| Тексты | `src/config/chat-bot.ts` | Общие для MAX и Telegram, редактируются в одном месте |
| Админка | `src/app/admin/obrashcheniya/` | Единый раздел обращений с фильтром по каналу, настройки каналов |

**Подписка на события (`allowed_updates`):** `message`, `callback_query`, `my_chat_member` (последнее —
чтобы знать, что пользователь заблокировал или разблокировал бота). Редактирования сообщений, реакции и
события групп не запрашиваются.

**Long Polling не используется.** Timeweb Apps запускает постоянный Node.js-сервер, Webhook принимает обычный
маршрут Next.js по HTTPS (порт 443 — из числа поддерживаемых Telegram: 443, 80, 88, 8443).

### Токен и секрет

- В Bot API токен — часть адреса запроса (`https://api.telegram.org/bot<токен>/метод`), иначе его передать
  нельзя. Поэтому адреса запросов **никогда не пишутся в журнал и не попадают в тексты ошибок**; описание
  ошибки от Telegram дополнительно очищается от строк вида `bot<id>:<…>`.
- Секрет Webhook передаётся в `setWebhook` (`secret_token`) и сверяется в каждом запросе за постоянное время.
  Без секрета события не принимаются вовсе (`503`), с неверным — `401` и ограничение частоты по адресу.
- Токен и секрет — только в переменных окружения хостинга; в базе, браузере и репозитории их нет.

### Таблицы (миграция `005_chat_channels`)

Таблицы MAX стали общими (`chat_clients`, `chat_messages`, `chat_notes`, `chat_events`) с полем `channel`;
данные MAX сохранены. Для Telegram:

- клиент — уникальная пара (`telegram`, ID пользователя); **username ключом не является** и обновляется при
  каждом сообщении. Один и тот же числовой ID в MAX и Telegram — разные клиенты;
- сообщение — `external_message_id` (message_id в Telegram), `external_chat_id`, `external_user_id`, ключ
  `external_mid = tg:<chat_id>:<message_id>` (уникальный), направление, текст, тип, время, статус отправки,
  метаданные вложений (тип, имя файла, размер, MIME — **без file_id, файлы не скачиваются**);
- событие — ключ `tg:<update_id>` (уникальный): повторная доставка Update не создаёт дублей;
- `chat_clients.person_id` — ручная связь карточек одного человека из разных каналов (см. ниже);
- заявки — существующая таблица `requests`, `channel = 'telegram'`, `chat_client_id` — карточка клиента.

### Защита от дублей, циклов и потерь

Как для MAX (общий код): атомарный захват события и каждого исходящего сообщения; автоматический повтор
только если запрос точно не дошёл (нет соединения) или Telegram вернул `429` (с паузой `retry_after`);
при неизвестном результате (тайм-аут после соединения) — статус `unknown` и повтор только вручную с
подтверждением; сообщения ботов и групп игнорируются; не больше 30 автоответов клиенту в минуту;
фоновая досылка раз в минуту после перезапуска. `403` от Telegram («bot was blocked by the user») —
статус «не отправлено», карточка помечается «бот остановлен клиентом»; новая переписка или разблокировка
бота клиентом снимает отметку.

## 2. Бот

- **/start** — приветствие от имени ООО «Интегро», краткое описание и inline-меню: «Оценка имущества»,
  «Судебная экспертиза», «Экспертные исследования», «Оставить заявку», «Связаться со специалистом».
  `/start <метка>` (ссылка `t.me/<бот>?start=<метка>`) сохраняет метку как источник обращения.
- **/help** — список команд; **/cancel** — отмена оформления заявки; неизвестная команда — «Такой команды
  нет» и справка.
- **Разделы** — объекты и цели оценки, виды судебных экспертиз, задачи экспертных исследований (тексты со
  страниц услуг сайта). Вопросы о документах — перечни с сайта; о цене или сроках — «сообщит специалист»,
  без цифр; прочее — «готового ответа нет» и кнопка «Связаться со специалистом».
- **Заявка** — согласие (кнопка) → имя → направление → описание → телефон (по желанию: кнопка
  «Отправить мой номер» — `request_contact`, номер текстом или «Пропустить») → удобное время связи (по
  желанию) → проверка: «Подтвердить», «Исправить» (любое поле), «Отменить». На каждом шаге есть «Назад» и
  «Отменить». После подтверждения — номер заявки (первые 8 символов идентификатора), запись в «Заявки»,
  письмо на почту, если настроен SMTP.
- **Телефон** берётся только из **собственного** контакта пользователя (`contact.user_id` совпадает с
  отправителем); пересланная чужая карточка не принимается. Бот не получает номер сам — только если
  пользователь нажал кнопку или написал его.
- **Неподдерживаемые форматы** (стикеры, фото, голосовые, файлы) — вежливая просьба написать текстом или
  оставить заявку; в истории — только тип и метаданные.
- **Нажатая inline-клавиатура снимается** (`editMessageReplyMarkup`), чтобы старые кнопки нельзя было нажать
  повторно; на каждое нажатие отправляется `answerCallbackQuery`.

### Режимы

Общие для каналов: **бот** отвечает по сценарию; **оператор** — бот молчит, сообщения клиента помечают диалог
«нужен ответ», нажатия старых кнопок получают уведомление «Сейчас с вами общается специалист». Переключение —
кнопками в карточке; ответ оператора сам включает режим оператора; «Вернуть диалог боту» — сценарий с меню.

### Админка

- `/admin/obrashcheniya` — все каналы; фильтры «Все каналы / MAX / Telegram», «Ждут ответа / В работе /
  Закрытые», период; поиск по имени, username, ID, телефону и тексту сообщений; страницы по 30. В строке —
  имя, username, ID пользователя, последнее сообщение, время, канал, статус, режим, заявки, «нужен ответ».
- `/admin/obrashcheniya/[id]` — история (номера сообщений Telegram), статус отправки каждого ответа и
  подтверждение платформы, повтор при ошибке, ответ, режимы, «нужен ответ», закрыть / вернуть в работу,
  заметки, связанные заявки, удаление.
- **«Тот же человек в других каналах»** — ручная связь карточек (поиск по имени, ID или телефону и кнопка
  «Связать»). Автоматически карточки не объединяются; связь не переносит данные и переписку и снимается
  кнопкой «Отвязать».
- `/admin/obrashcheniya/nastroyki` — переменные (без значений), «Проверить подключение» (getMe и
  getWebhookInfo: адрес, очередь, последняя ошибка доставки), «Зарегистрировать Webhook» (setWebhook),
  «Удалить Webhook».

Всё — только после входа в существующую админку; каждое действие проверяет сессию на сервере.

## 3. Что настроить

### BotFather

1. Создать бота (`/newbot`) или открыть существующего; получить токен.
2. Рекомендуется (необязательно): `/setdescription` и `/setabouttext` — описание без цен и обещаний;
   `/setcommands`:
   ```
   start - Главное меню
   help - Справка
   cancel - Отменить оформление заявки
   ```
3. Privacy mode и добавление в группы для работы не нужны: бот обрабатывает только личные чаты.

### Переменные окружения (Timeweb)

| Переменная | Значение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен от @BotFather (`123456789:AAE…`) |
| `TELEGRAM_WEBHOOK_SECRET` | 32–256 символов `[A-Za-z0-9_-]`, например `openssl rand -hex 32`. Не совпадает с секретом MAX |
| `TELEGRAM_WEBHOOK_URL` | Необязательно. По умолчанию `SITE_URL` + `/api/telegram/webhook` |
| `TELEGRAM_BOT_USERNAME` | Необязательно. Username бота без «@» — для ссылки в настройках и сверки с getMe |

`TELEGRAM_API_BASE_URL` — только для автотестов, в production **не задавать**.

### URL Webhook

```
https://intsoftholding.ru/api/telegram/webhook
```

### Действия

1. Задать переменные и перезапустить приложение — в журнале `[telegram] bot on, webhook https://…`.
2. Админка → «Обращения» → «Настройки каналов» → блок Telegram → «Проверить подключение» (имя бота).
3. «Зарегистрировать Webhook», затем снова «Проверить подключение»: адрес сайта с пометкой «этот сайт»,
   очередь 0, без последней ошибки.

База: таблицы обновляются автоматически при запуске (миграция `005_chat_channels`, данные сохраняются).

## 4. Проверка: от /start до ответа оператора

1. Отправьте боту `/start` → приветствие с меню. В «Обращениях» (фильтр Telegram) — карточка: имя,
   username, ID, «Запуск бота», ответ бота «Отправлено, платформа подтвердила».
2. Нажмите каждую кнопку меню → приходят разделы; нажатые кнопки исчезают.
3. «Оставить заявку» → согласие → имя → направление → описание → «Отправить мой номер» (клавиатура
   исчезает после шага) → «Пропустить» → «Подтвердить» → «Заявка № … принята»; в «Заявках» — запись
   с пометкой Telegram и ссылкой на диалог.
4. Отправьте `/start` ещё раз и любое сообщение → та же карточка, без дублей.
5. В карточке ответьте → сообщение приходит в Telegram, в админке — «Telegram подтвердил отправку».
6. Напишите боту → бот молчит, сообщение появляется в карточке (до 10 секунд), «Нужен ответ».
7. «Вернуть диалог боту» → `/help` → бот отвечает.
8. Заблокируйте бота в Telegram → карточка «Бот остановлен клиентом», ответ не отправляется; разблокируйте →
   отправка снова доступна.
9. «Проверить подключение» — нет последней ошибки доставки.

Если на шаге 1 карточки нет: «Проверить подключение» покажет последнюю ошибку доставки Webhook из Telegram;
журнал приложения — строки `[telegram] …`.

## 5. Ограничения и что не проверено

- **Реальные запросы к Telegram Bot API не выполнялись.** Нужна проверка по разделу 4.
- Бот может писать только пользователям, которые сами начали с ним чат и не заблокировали его. Написать
  человеку первым по username или номеру телефона нельзя.
- Ограничения Telegram: текст — до 4096 символов (в админке — до 4000, общее ограничение с MAX), данные
  кнопки — до 64 байт, около 1 сообщения в секунду в один чат и около 30 в секунду всего (`429` с
  `retry_after` обрабатывается).
- Кнопка «Отправить мой номер» в Telegram — кнопка обычной клавиатуры: на этом шаге остальные кнопки
  становятся текстовыми (их подписи бот распознаёт), после шага клавиатура убирается сообщением «Принято.».
- Кнопка Telegram на сайте ведёт в бота: `https://t.me/IntSoftHoldingBot?start=site`. Метка `site` сохраняется
  как источник обращения в карточке клиента (если человек уже запускал бота раньше, источник остаётся прежним).
- Удаление переписки — вручную в карточке; сроки хранения не автоматизированы (см. `LEGAL_REVIEW.md`, п. 4.11).
- Ограничения частоты и фоновая досылка рассчитаны на один экземпляр приложения.

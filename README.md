# Сайт ООО «Интегро»

Корпоративный сайт: оценочная деятельность, судебная экспертиза, экспертные исследования.

Стек: Next.js 16 (App Router), React 19, TypeScript, Tailwind CSS 4, Lucide. Шрифт — IBM Plex Sans (SIL OFL 1.1),
подключён локально через `next/font/local` (`src/fonts/`), без запросов к внешним сервисам. Одно Next.js-приложение,
без отдельного backend, базы данных и внешних платных сервисов. Отправка формы — Server Action + SMTP.

## Команды

```bash
npm ci              # установка зависимостей
npm run dev         # разработка, http://localhost:3000
npm run typecheck   # проверка TypeScript
npm run lint        # ESLint
npm run build       # production-сборка
npm start           # запуск production-сервера (порт из переменной PORT, по умолчанию 3000)
npm test            # юнит-тесты; с TEST_DATABASE_URL — ещё и тесты с PostgreSQL
npm run test:e2e    # сквозные тесты в браузере (нужны npm run build и TEST_DATABASE_URL)
```

Node.js: 20.9 или новее (рекомендуется 22, см. `.nvmrc`).

## Статьи

Статьи — Markdown-файлы в `content/articles/`. Новый файл автоматически появляется в списке `/stati`, на главной,
в блоках «Статьи по теме» на страницах связанных услуг и в `sitemap.xml`. Адрес статьи — имя файла:
`content/articles/primer.md` → `/stati/primer`.

```markdown
---
title: Заголовок статьи
description: Краткий анонс для карточки и поисковиков
category: ocenka            # ocenka | ekspertiza | rabota (src/lib/articles.ts)
published: 2026-10-17
updated: 2026-11-01         # необязательно
services: [ocenka]          # связанные услуги, необязательно
draft: true                 # черновик: виден только в режиме разработки
---

Текст в Markdown: ## подзаголовки (из них строится оглавление), списки, таблицы, > примечания, ссылки.
```

Статьи сортируются по дате публикации (новые сверху). Для каждой формируются title, description, canonical,
Open Graph и разметка Article.

## Переменные окружения

См. `.env.example`. Кратко:

- `SITE_URL` — основной домен (`https://...`). Нужен **и при сборке, и при запуске**. Пока не задан, сайт
  отдаёт `noindex` и `Disallow: /`, canonical не выводится.
- `DATABASE_URL` — строка подключения к PostgreSQL, где хранятся заявки. TLS — параметром `sslmode` в адресе
  или `DATABASE_SSL=true`; корневой сертификат провайдера — в `DATABASE_CA_CERT`.
- `ADMIN_PASSWORD` — пароль панели заявок `/admin`, не короче 12 символов. Пустой — вход отключён.
- `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASSWORD`, `MAIL_FROM`, `MAIL_TO` — уведомления
  о заявках на почту. Обязательны `SMTP_HOST`, `SMTP_USER`, `SMTP_PASSWORD`; без `MAIL_TO` письма идут на почту
  компании (info@intsoftholding.ru). При запуске в журнал пишется строка `[mail] notifications on/off`. Без базы и без SMTP форма отключена и честно сообщает, что приём заявок не подключён.

- `MAX_BOT_TOKEN`, `MAX_WEBHOOK_SECRET`, `MAX_WEBHOOK_URL`, `MAX_API_CA_CERT` — чат-бот MAX
  (см. [MAX_INTEGRATION.md](MAX_INTEGRATION.md)). Без токена и секрета бот выключен, при запуске в журнал
  пишется строка `[max] chat bot off/on`.
- `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`, `TELEGRAM_WEBHOOK_URL`, `TELEGRAM_BOT_USERNAME` — Telegram-бот
  (см. [TELEGRAM_INTEGRATION.md](TELEGRAM_INTEGRATION.md)); в журнале — строка `[telegram] bot off/on`.

- `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` — браузерные push-уведомления администратору.
- `BACKUP_ENCRYPTION_KEY`, `BACKUP_S3_*`, `BACKUP_HOUR_MSK`, `BACKUP_RETENTION_DAYS` — шифрованные резервные копии
  базы во внешнем хранилище (см. [ADMIN_OPERATIONS.md](ADMIN_OPERATIONS.md)).

Секреты задаются только в панели хостинга, в репозиторий не попадают (`.env*` в `.gitignore`).

## Чат-боты MAX и Telegram

Общая система обращений из мессенджеров (`src/lib/chat/`): Webhook каждого канала
(`/api/max/webhook`, `/api/telegram/webhook`) сохраняет события, общий сценарий отвечает клиенту по меню и
оформляет заявку (в ту же таблицу `requests`), переписка всех каналов видна в админке в разделе «Обращения»
(`/admin/obrashcheniya`, фильтр по каналу), оператор отвечает оттуда — ответ уходит клиенту в его мессенджер.
Каналы подключаются адаптерами (`src/lib/max/adapter.ts`, `src/lib/telegram/adapter.ts`, список —
`src/lib/chat/registry.ts`). Тексты и кнопки ботов — в `src/config/chat-bot.ts`. Подключение, проверка и
ограничения — [MAX_INTEGRATION.md](MAX_INTEGRATION.md) и [TELEGRAM_INTEGRATION.md](TELEGRAM_INTEGRATION.md).

## Форма заявки

`src/app/(site)/kontakty/actions.ts` — серверная валидация, защита от спама (скрытое поле-ловушка, минимальное
время заполнения, ограничение 5 заявок за 14 минут с одного IP в памяти процесса, запись удаляется не позднее
15 минут), сохранение заявки в базу и письмо-уведомление через `nodemailer`.

- Успех показывается только после записи в базу. Если база не настроена, но настроен SMTP, — после приёма письма
  почтовым сервером (прежний режим). Ошибка базы — сообщение «Не удалось отправить заявку», введённые данные
  остаются в форме для повтора.
- Защита от дубликатов: браузер создаёт ключ отправки (UUID) при открытии формы, в базе на него стоит уникальный
  индекс. Двойное нажатие или повтор после сбоя сети не создают вторую заявку; ключ меняется после успеха.
- В журнал сервера пишутся только коды ошибок, без данных заявок.

Согласие на обработку ПД — отдельное поле без предварительной отметки, текст раскрывается в форме; дата редакции
согласия сохраняется с заявкой и попадает в письмо. При изменении формы обновите политику (см. `LEGAL_REVIEW.md`).

Подойдёт SMTP почты на домене компании (например, почта Timeweb, Яндекс 360, Mail.ru для бизнеса).
Для Яндекс 360: `SMTP_HOST=smtp.yandex.ru`, `SMTP_PORT=465`, `SMTP_SECURE=true`, пароль приложения в `SMTP_PASSWORD`.

## Панель заявок `/admin`

Закрытый раздел для работы с заявками: таблица (дата, имя, телефон, услуга, статус), сортировка по дате, поиск
по имени, телефону и email, фильтр по статусу, карточка заявки со сменой статуса и внутренними заметками,
удаление с подтверждением, счётчики новых и всех заявок, выгрузка в CSV (все или текущая выборка).

Статусы: Новая, В работе, Ожидает ответа клиента, Завершена, Отклонена.

Как устроено:

| Что | Где |
| --- | --- |
| Подключение к базе, TLS, миграции | `src/lib/db/index.ts`, `src/lib/db/config.ts`, `src/lib/db/migrations.ts` |
| Заявки: запись, поиск, изменение, удаление | `src/lib/requests/` |
| Пароль, сессии, лимит попыток входа | `src/lib/admin/` |
| Страницы и серверные действия | `src/app/admin/` |
| Выгрузка CSV | `src/app/api/admin/export/route.ts` |

Безопасность:

- **Пароль.** Берётся только из `ADMIN_PASSWORD` на сервере, сравнивается за постоянное время. В базу, HTML и
  ответы не попадает. Если переменная пуста или короче 12 символов, вход отключён, а страница входа сообщает,
  что нужно настроить сервер.
- **Сессия.** Случайный токен в cookie `__Host-integro-admin` с флагами HttpOnly, Secure, SameSite=Lax. Срок —
  8 часов. В базе хранится только SHA-256 токена. Выход удаляет сессию на сервере. Кнопка «Завершить все сессии»
  — например, после смены пароля.
- **Перебор пароля.** Не более 5 неудачных попыток с одного адреса и 30 со всех адресов за 15 минут, плюс
  задержка после ошибки. Учёт ведётся в базе, поэтому переживает перезапуск.
- **Проверка доступа.** Сессию проверяет каждая страница, каждое серверное действие и API выгрузки, а не только
  интерфейс. Без сессии API отвечает 401.
- **CSRF.** Изменения выполняются только Server Actions (POST): Next.js сверяет заголовки Origin и Host, а cookie
  с SameSite=Lax не уходит с межсайтовыми POST-запросами.
- **Индексация и кеш.** Для `/admin` и `/api/admin` выставлены заголовки `X-Robots-Tag: noindex` и
  `Cache-Control: no-store`, плюс запрет встраивания во фреймы.
- **CSV.** UTF-8 с BOM, разделитель «;». Значения, начинающиеся с `=`, `+`, `-`, `@`, табуляции или перевода
  строки, экранируются апострофом (защита от CSV-инъекций).

### База данных: почему PostgreSQL в Timeweb Cloud

Файловая система приложения в Timeweb App Platform не подходит для хранения данных: при деплое приложение
собирается заново, и сохранность локальных файлов не гарантируется. Поэтому заявки хранятся во внешней
управляемой базе Timeweb Cloud (PostgreSQL). Это отдельная платная услуга. Драйвер `pg`, схема и индексы создаются
миграциями автоматически при запуске (`[db] connected, schema is up to date` в журнале приложения).

### Настройка в Timeweb (один раз)

1. **Создайте базу.** Панель Timeweb Cloud → «Базы данных» → создать → PostgreSQL (версия 14 или новее).
   Регион — **Россия** (требование локализации, см. `LEGAL_REVIEW.md`, п. 2.9). Минимальной конфигурации
   достаточно. Включите автоматическое резервное копирование.
2. **Сеть и TLS.** Включите публичный IPv4 базы (или приватную сеть с приложением). В конец строки подключения
   добавьте `?sslmode=require` — соединение будет зашифровано. Для проверки подлинности сервера скачайте
   корневой сертификат в карточке базы, вставьте его в `DATABASE_CA_CERT` и замените режим на `verify-ca` (при
   подключении по IP) или `verify-full` (по доменному имени). Режимы описаны в `.env.example`.
3. **Пользователь и база.** В карточке базы возьмите хост, порт, имя пользователя, пароль и имя базы. У
   пользователя должны быть права на создание таблиц в этой базе (для миграций).
4. **Переменные приложения.** «Apps» → ваше приложение → настройки → переменные окружения:
   - `DATABASE_URL=postgresql://ПОЛЬЗОВАТЕЛЬ:ПАРОЛЬ@ХОСТ:5432/ИМЯ_БАЗЫ?sslmode=require` — пароль можно вставить
     как есть: панель Timeweb раскодирует значения переменных, поэтому сайт разбирает строку сам и принимает
     пароль и со спецсимволами, и в закодированном виде;
   - `ADMIN_PASSWORD=` — длинный случайный пароль, 16 символов и больше;
   - при необходимости `DATABASE_CA_CERT` (см. шаг 2).
5. **Перезапуск.** Сохраните переменные и перезапустите приложение (или запустите повторный деплой) — переменные
   читаются при запуске. В журнале приложения появятся строки `[db] connecting to пользователь@хост:порт/база, TLS …`
   (без пароля) и `[db] connected, schema is up to date`.
   Если там `[db] database is unavailable: …` — проверьте адрес, пароль и сетевой доступ.
6. **Вход.** Откройте `https://intsoftholding.ru/admin`, введите пароль. Отправьте тестовую заявку на странице
   «Контакты» и убедитесь, что она появилась в таблице.

Смена пароля: измените `ADMIN_PASSWORD`, перезапустите приложение, войдите с новым паролем и нажмите «Завершить все
сессии администратора».

## Тесты

- `npm test` — юнит-тесты (CSV, фильтры, пароль) и, если задана `TEST_DATABASE_URL`, тесты с PostgreSQL:
  миграции, дубликаты, поиск, сортировка, статусы, сессии, блокировка перебора.
- `npm run test:e2e` — сквозные тесты Playwright на собранном проекте. Проверяют: без входа нет доступа
  (страницы, API, поддельный cookie); неверный пароль; вход, флаги cookie, выход и отзыв токена; заявка с сайта
  появляется в админке без дубликата при двойном нажатии; ошибка базы не даёт ложного успеха; статус и заметки
  сохраняются после перезагрузки; поиск, фильтр, удаление; CSV после входа с кириллицей и экранированием формул.
  Чат-боты проверяются с имитациями MAX Bot API (`tests/e2e/max-mock-server.mjs`, порт 3203) и Telegram Bot API
  (`tests/e2e/telegram-mock-server.mjs`, порт 3204): секрет Webhook, повторная доставка, кнопки меню, заявка,
  ответ оператора из админки доходит до API, режимы, регистрация Webhook.

`TEST_DATABASE_URL` — **отдельная тестовая база**: тесты очищают в ней все таблицы.

## Деплой на Timeweb Cloud (GitHub → push в main → автодеплой)

Приложению нужен Node.js-сервер (Server Actions, динамическая страница «Контакты»), поэтому статический
хостинг не подходит. Возможны два варианта в Timeweb Cloud Apps — выберите один.

### Вариант A. Apps → Backend → Node.js / Next.js

1. Панель Timeweb Cloud → «Apps» → «Создать» → тип Backend, фреймворк Next.js (если его нет — Node.js).
2. Подключите GitHub-аккаунт и выберите репозиторий `difast/integro`, ветку `main`.
3. Версия Node.js: 22 (или 20).
4. Команда сборки: `npm ci && npm run build`.
5. Команда запуска: `npm start`. Приложение слушает порт из переменной `PORT` (по умолчанию 3000);
   если панель требует указать порт — укажите 3000.
6. Переменные окружения: `SITE_URL`, `DATABASE_URL`, `ADMIN_PASSWORD` и при необходимости SMTP-переменные из
   `.env.example`. `SITE_URL` должна быть доступна и на этапе сборки. Настройка базы — раздел «Панель заявок».
7. Включите автоматический деплой при push в выбранную ветку.

### Вариант B. Apps → Dockerfile

1. «Apps» → «Создать» → Docker / Dockerfile, репозиторий `difast/integro`, ветка `main`.
2. Используется `Dockerfile` из корня (Node 22 Alpine, standalone-сборка, порт 3000).
3. `SITE_URL` нужно передать как build-аргумент (если панель позволяет) и как переменную окружения.
   SMTP-переменные — переменные окружения контейнера.
4. Включите автодеплой при push в `main`.

После первого деплоя: привяжите домен и SSL в панели, задайте `SITE_URL`, пересоберите приложение,
проверьте `https://домен/robots.txt` и `https://домен/sitemap.xml` и отправьте тестовую заявку.

Названия пунктов панели Timeweb могут отличаться — сверяйтесь с актуальной документацией
(timeweb.cloud/docs/apps).

GitHub Actions (`.github/workflows/ci.yml`) только проверяет сборку при push и pull request; деплой
выполняет Timeweb.

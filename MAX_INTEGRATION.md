# Чат-бот MAX: интеграция с сайтом и панелью заявок

Клиент пишет боту в MAX → событие приходит на Webhook сайта → обращение и сообщения сохраняются в базе
и видны в админке (раздел «Обращения», фильтр «MAX») → оператор отвечает из админки → ответ уходит клиенту в MAX через
официальный Bot API.

**Статус проверки (20.10.2026).** Код и тесты готовы. Запросы к настоящему MAX API **не выполнялись**:
в среде разработки нет токена бота, а домены `max.ru`, `dev.max.ru`, `platform-api2.max.ru` недоступны.
Интеграцию нужно проверить на сервере по разделу «Проверка» ниже — до этого она не считается работающей.

## 1. Как устроено

| Часть | Где | Что делает |
| --- | --- | --- |
| Webhook | `src/app/api/max/webhook/route.ts` → `src/lib/chat/webhook.ts` | `POST /api/max/webhook`: проверяет `X-Max-Bot-Api-Secret`, размер и JSON, сохраняет событие в `chat_events` (уникальный ключ — защита от повторной доставки) и сразу отвечает `200`. Обработка — после ответа (`after()` из Next.js) |
| Обработка (общая для каналов) | `src/lib/chat/processor.ts` | В одной транзакции: карточка клиента, входящее сообщение, сценарий, заявка, ответы в очередь. После фиксации — отправка ответов по одному через адаптер канала |
| Адаптер MAX | `src/lib/max/adapter.ts` | Отправка сообщений и ответы на нажатия кнопок через MAX API |
| Сценарий (общий) | `src/lib/chat/scenario.ts` | Чистая функция «состояние + ввод → ответы»: меню, разделы, оформление заявки, передача специалисту |
| Тексты и кнопки (общие) | `src/config/chat-bot.ts` | **Все тексты ботов в одном месте.** Только сведения, опубликованные на сайте |
| API MAX | `src/lib/max/api.ts` | Запросы к `https://platform-api2.max.ru`, токен — только в заголовке `Authorization` |
| Разбор событий | `src/lib/max/types.ts` | Перевод событий MAX в общий вид, ключи дедупликации, вложения без ссылок и токенов |
| Админка (общая) | `src/app/admin/obrashcheniya/` | Список обращений всех каналов, карточка с перепиской и ответом, настройки и регистрация Webhook |
| Фоновая досылка | `src/instrumentation.ts` → `sweepChats()` | Раз в минуту доделывает события и отправки, прерванные перезапуском |

С 20.10.2026 MAX — один из каналов общей системы обращений (вместе с Telegram, см. `TELEGRAM_INTEGRATION.md`).
Прежние адреса `/admin/max…` перенаправляют в общий раздел.

**Почему не Long Polling.** Timeweb Apps запускает постоянный Node.js-сервер (`npm start`), поэтому события
принимает обычный маршрут Next.js по HTTPS. Отдельный сервис или процесс не нужен. Long Polling в коде нет.

**Почему не официальный npm-пакет `@maxhub/max-bot-api`.** Его сессии по умолчанию хранятся в памяти, Webhook
поднимает отдельный HTTP-сервер, а `fetch` нельзя настроить на дополнительный корневой сертификат. Методы и
поля взяты из этого официального клиента (github.com/max-messenger/max-bot-api-client-ts, версия 1.0.2),
транспорт написан на `node:https` с тайм-аутами.

### Используемые методы MAX Bot API

| Метод | Зачем |
| --- | --- |
| `GET /me` | Проверка токена («Проверить подключение») |
| `GET /subscriptions` | Список подписок Webhook |
| `POST /subscriptions` — `{ url, secret, update_types }` | Регистрация Webhook |
| `DELETE /subscriptions?url=` | Отписка |
| `POST /messages?user_id=` — `{ text, attachments? }` | Сообщение клиенту (ответы бота и оператора), клавиатура — вложение `inline_keyboard` |
| `POST /answers?callback_id=` — `{ message }` или `{ notification }` | Ответ на нажатие кнопки: у прежнего сообщения убирается клавиатура (защита от повторных нажатий) |

Подписка на события: `bot_started`, `bot_stopped`, `message_created`, `message_callback`, `dialog_removed`.

### Таблицы (миграции `004_max_bot` и `005_chat_channels`, `src/lib/db/migrations.ts`)

Миграция `005` переименовала таблицы `max_*` в общие `chat_*` и добавила канал (`channel`); данные MAX
сохранены. Описание ниже — в терминах общих таблиц.

- `chat_clients` — карточка клиента и диалога (у пользователя с ботом один диалог, поэтому отдельная таблица
  диалогов не заведена): канал и ID пользователя в канале (уникальная пара — ключ связи повторных обращений), chat_id, имя,
  фамилия, username, метка запуска, телефон (только если клиент сам указал), статус (`open`/`closed`), режим
  (`bot`/`operator`), «нужен ответ», «клиент остановил бота», шаг сценария, согласие (время и редакция), даты
  первого обращения, последней активности и последнего сообщения.
- `chat_messages` — входящие и исходящие: направление, автор (клиент/бот/оператор), тип, текст, метаданные
  вложений (тип, имя файла, размер — **файлы не загружаются**), внешний ID (`mid`, уникальный), ключ
  идемпотентности (уникальный), статус (`received`, `pending`, `sending`, `sent`, `failed`, `unknown`), ошибка,
  время события.
- `chat_notes` — внутренние заметки сотрудников.
- `chat_events` — журнал входящих событий: уникальный ключ (`message:<mid>`, `callback:<callback_id>`, для
  остальных — тип+пользователь+время), статус обработки, число попыток. Исходный JSON удаляется после обработки.
- `requests` — **существующая таблица заявок**: добавлены `channel` (`site`/`max`/`telegram`) и `chat_client_id`.

### Защита от дублей, циклов и потерь

- **Повторная доставка события** — тот же ключ в `chat_events` не вставляется второй раз, ответ MAX — `200`.
- **Повторная обработка** — событие захватывается атомарно (`pending/failed → processing`), всё внутри одной
  транзакции; при ошибке транзакция откатывается и событие повторяется (до 5 попыток).
- **Повторная отправка** — каждое исходящее сообщение захватывается атомарно (`pending → sending`). Повтор
  выполняется автоматически только при ошибках, когда запрос **точно не дошёл** (нет соединения, `429`, `503`).
  Если соединение было, но ответа нет (тайм-аут 10 с, обрыв), статус — `unknown`, и повтор возможен только
  вручную, с подтверждением оператора.
- **Ответ оператора** — у формы ключ идемпотентности: двойное нажатие или повтор запроса не отправит сообщение
  дважды.
- **Циклы** — сообщения ботов (в том числе собственные) и групповые чаты игнорируются; не больше 30 автоответов
  клиенту в минуту, дальше бот замолкает и помечает диалог «нужен ответ».
- **Перезапуск сервера** — фоновая проверка раз в минуту доделывает необработанные события и неотправленные
  сообщения; прерванная отправка помечается `unknown` (без автоматического повтора).
- **База недоступна** — Webhook отвечает `503`, событие не теряется, если MAX доставит его повторно.

## 2. Сценарий бота

Первое обращение (`bot_started` или первое сообщение): приветствие от имени ООО «Интегро», краткое описание и
меню: «Оценка имущества», «Судебная экспертиза», «Экспертные исследования», «Оставить заявку», «Связаться со
специалистом».

- **Разделы** — объекты и цели оценки, виды судебных экспертиз, задачи экспертных исследований (тексты
  совпадают со страницами услуг на сайте).
- **Свободный текст** — команды «меню», «/start», приветствия; ключевые слова разделов; вопрос о документах —
  перечни со страниц услуг; вопрос о цене или сроках — «сообщит специалист», без цифр. Остальное — «готового
  ответа нет» и кнопка «Связаться со специалистом». Языковые модели и сторонние AI-сервисы не используются.
- **Заявка** — согласие (кнопка, со ссылками на документы и предупреждением не присылать паспортные данные,
  реквизиты и конфиденциальные документы) → имя → направление → описание → телефон (по желанию: кнопка
  «Отправить мой номер» или текстом, можно пропустить) → удобное время связи (по желанию) → проверка с кнопками
  «Подтвердить», «Исправить» (любое поле), «Отменить» → запись в `requests` → номер заявки клиенту (первые
  8 символов идентификатора) → письмо на почту, если настроен SMTP.
- **Связаться со специалистом** — диалог помечается «нужен ответ», клиенту — подтверждение; дальнейшие
  сообщения передаются специалисту (подтверждение пересылки — один раз).
- **Вложения** — сохраняются только тип и метаданные; клиенту — напоминание не отправлять конфиденциальные
  документы.

### Автоматические сообщения спустя время

Общие для MAX и Telegram, настраиваются в `src/config/chat-bot.ts` (`botFollowUps`, тексты — `botTexts`):

- **Незавершённая заявка** — если клиент остановился на одном из шагов заявки: напоминание через 2 часа и
  последнее через 24 часа после его последнего сообщения, с кнопками «Продолжить заявку» и «Отменить».
  Любое сообщение клиента сбрасывает отсчёт. Не отправляется в режиме оператора, закрытым диалогам,
  заблокировавшим бота и если с последней активности прошло больше 3 дней.
- **Опрос после закрытия** — через 30 минут после закрытия диалога оператором: «Остались ли у вас вопросы?»
  с кнопками «Вопросов нет» (диалог остаётся закрытым) и «Есть вопрос» (диалог возвращается в работу
  с отметкой «нужен ответ»). Не отправляется, если диалог снова открыт или клиент написал раньше.
- Расписание хранится в базе (`chat_clients.reminder_stage`, `survey_due_at`, миграция `006_chat_followups`)
  и проверяется фоновой задачей раз в минуту; каждое сообщение захватывается под блокировкой строки и не
  уходит дважды. В карточке клиента видно, сколько напоминаний отправлено и когда запланирован опрос.
- Только служебные сообщения по обращению самого клиента, без рекламы; первыми бот не пишет.

### Режимы

- **Бот** — отвечает по сценарию.
- **Оператор** — бот не отвечает автоматически; каждое сообщение клиента помечает диалог «нужен ответ»;
  нажатия старых кнопок получают уведомление «Сейчас с вами общается специалист».
- Переключение — кнопки в карточке («Взять в работу» / «Вернуть диалог боту»). **Ответ оператора сам включает
  режим оператора.** При возврате боту незавершённая заявка сбрасывается, сценарий начинается с меню.

### Админка

- `/admin/obrashcheniya` — список (фильтр по каналу): имя, ID MAX, последнее сообщение, время активности, статус, режим, наличие заявок,
  «нужен ответ» (такие диалоги — сверху). Поиск по имени, username, ID, телефону (из карточки и заявок) и тексту
  сообщений; фильтры «Ждут ответа / В работе / Закрытые» и период; страницы по 30. Обновляется каждые 20 с.
- `/admin/obrashcheniya/[id]` — переписка по времени (по 50 сообщений, «Показать более ранние»), статус отправки каждого
  ответа, повтор при ошибке, ответ клиенту, режим, «нужен ответ», закрыть / вернуть в работу, заметки, связанные
  заявки, удаление карточки. Обновляется каждые 10 с, введённый текст при этом сохраняется.
- `/admin/obrashcheniya/nastroyki` — какие переменные заданы (без значений), проверка подключения, регистрация и удаление
  Webhook.
- В карточке заявки — канал и ссылка на диалог; в списке заявок — пометка «MAX».

Все страницы и действия — только после входа в существующую админку (`ADMIN_PASSWORD`, сессия в базе).
Публичных страниц и API с перепиской нет.

## 3. Что настроить

### Переменные окружения (Timeweb → приложение → переменные)

| Переменная | Значение |
| --- | --- |
| `MAX_BOT_TOKEN` | Токен бота из @MasterBot. Только в переменных хостинга |
| `MAX_WEBHOOK_SECRET` | Случайная строка 32–256 символов `[A-Za-z0-9_-]`, например `openssl rand -hex 32` |
| `MAX_WEBHOOK_URL` | Необязательно. По умолчанию `SITE_URL` + `/api/max/webhook` |
| `MAX_API_CA_CERT` | Необязательно. Корневой сертификат (PEM), если проверка подключения сообщает об ошибке TLS |
| `DATABASE_URL`, `ADMIN_PASSWORD`, `SITE_URL` | Уже настроены для сайта |

`MAX_API_BASE_URL` — только для автотестов, в production **не задавать**.

### Публичный URL Webhook

```
https://intsoftholding.ru/api/max/webhook
```

Домен должен открываться по HTTPS с действительным сертификатом (Timeweb выпускает его для подключённого домена).

### Действия на платформе MAX

1. Токен бота — в @MasterBot (если ещё не получен). Ссылка на бота на сайте не менялась:
   `https://max.ru/id9734021152_bot`.
2. Задать переменные в Timeweb и перезапустить приложение. В журнале должно появиться
   `[max] chat bot on, webhook https://intsoftholding.ru/api/max/webhook`.
3. Админка → «Обращения» → «Настройки каналов» → блок MAX → **«Проверить подключение»**: должны отобразиться имя и id
   бота. Ошибка `401` — неверный токен; ошибка TLS — см. «Сертификат» ниже.
4. **«Зарегистрировать Webhook»** — сайт вызывает `POST /subscriptions` с адресом, секретом и списком событий.
   Затем ещё раз «Проверить подключение» — в подписках будет адрес сайта.

Если на платформе для бота доступны другие настройки (описание, аватар, команды) — они на работу интеграции
не влияют.

### База данных

Ничего вручную делать не нужно: таблицы создаются и обновляются автоматически при запуске (миграции `004_max_bot`,
`005_chat_channels`; существующие данные сохраняются). Рекомендуется включить резервное копирование базы в Timeweb.

### Сертификат platform-api2.max.ru

Сторонние интеграции с MAX подключают для `platform-api2.max.ru` корневой сертификат Минцифры
(Russian Trusted Root CA). Нужен ли он для Node.js на сервере Timeweb, проверить из среды разработки не удалось.
Если «Проверить подключение» сообщает об ошибке сертификата: скачайте корневой сертификат Минцифры с
официального сайта (gosuslugi.ru/crt), вставьте содержимое PEM в `MAX_API_CA_CERT` и перезапустите приложение.
Сертификат применяется **только к запросам к MAX API**, остальной трафик сайта не затрагивается.

## 4. Проверка: от первого сообщения до ответа оператора

1. Откройте бота в MAX, нажмите «Начать» → приходит приветствие с меню.
   В админке «Обращения» появляется карточка (имя, ID MAX, «Запуск бота», ответ бота со статусом
   «Отправлено в MAX»).
2. Нажмите «Оценка имущества» → «Цели оценки» → «Главное меню». У нажатого сообщения должны пропадать кнопки.
3. «Оставить заявку» → согласие → имя → направление → описание → «Отправить мой номер» или «Пропустить» →
   время связи → «Подтвердить». Клиенту приходит «Заявка № … принята», в разделе «Заявки» — новая заявка
   с пометкой MAX, в карточке клиента — ссылка на неё.
4. Напишите произвольный вопрос → бот предлагает связаться со специалистом. Нажмите «Связаться со
   специалистом» → в списке диалог поднимается наверх с отметкой «Нужен ответ».
5. В карточке напишите ответ и нажмите «Отправить в MAX» → сообщение приходит клиенту в MAX, в истории —
   «Отправлено, платформа подтвердила», режим — «Оператор».
6. Напишите боту ещё раз → бот молчит, сообщение появляется в карточке (до 10 секунд), диалог снова «Нужен ответ».
7. «Вернуть диалог боту» → напишите «меню» → бот отвечает.
8. Остановите бота в MAX → в карточке «Бот остановлен клиентом», отправка недоступна; «Начать» снова — доступна.

Если на шаге 1 карточка не появилась: проверьте журнал приложения (`[max] …`), подписку («Проверить
подключение») и что сайт открывается по HTTPS. Запрос с неверным секретом в журнале выглядит как
`[max] webhook request with an invalid secret rejected`.

## 5. Ограничения и что не проверено

- **Реальные запросы к MAX API не выполнялись** (нет токена и доступа к доменам MAX из среды разработки).
  Методы и поля взяты из официального клиента MAX; поведение платформы (повторная доставка Webhook при ошибке,
  её интервалы, лимиты запросов) по документации не сверено. Код рассчитан на оба случая: повторная доставка
  не создаёт дублей, `429` и `Retry-After` обрабатываются.
- `POST /answers` с `{ message: { text, attachments: [] } }` должен убирать клавиатуру у нажатого сообщения;
  если MAX ведёт себя иначе, это не мешает сценарию (ошибка только записывается в журнал).
- Бот может писать только пользователям, которые сами начали диалог с ботом; после «остановить бота» отправка
  невозможна до нового обращения клиента. Рассылок и сообщений «первым» нет.
- Метка источника (`payload` в `bot_started`) сохраняется, если MAX её передаёт; ссылка на сайте не менялась,
  поэтому сейчас источник «не определён». Формат deep-link с меткой в официальном клиенте не описан.
- Телефон из кнопки «Отправить мой номер» берётся из vCard, которую присылает MAX; формат на реальных данных
  не проверен — при ошибке бот просит ввести номер текстом.
- Срок хранения переписки автоматически не ограничен: удаление — вручную в карточке клиента. Срок нужно
  определить (см. `LEGAL_REVIEW.md`, п. 4.10).
- Ограничение частоты неудачных запросов к Webhook и защита фоновой проверки от параллельного запуска рассчитаны
  на один экземпляр приложения (как и остальной сайт).
- Перед приёмом заявок через бота нужно обновить политику и согласие — см. `LEGAL_REVIEW.md`, п. 4.10.
